# ADR 0018 — Auth, device owner and test servers (T-103)

- Status: accepted (2026-10-03)
- Requirements: FR-SYN-01, FR-SYN-05, NFR-PERF-08, ADR 0007

## Decision

1. **Sign-in**: email magic link (`signInWithOtp`, redirect to the app origin) and Google OAuth; persistent
   session in supabase-js. A `/auth/confirm?token_hash&type` route verifies token-hash links (custom email
   templates; the E2E suite signs in through it with `admin.generateLink`).
2. **Guard**: with a project configured, every app route needs a session (`AuthGate` → `/login`); local-only
   builds have no guard and no sync.
3. **Device owner** (ADR 0007): the first account to sign in owns the local database (`meta.ownerUserId`) and
   adopts data made in local-only mode. Another account finds a blocking screen: "Remove it and continue" (wipe
   the local database) or sign out — rows are never pushed under the wrong account. Sync starts only for the owner
   and stops on sign-out.
4. **Sign-out** dialog with "Remove data from this device" (clears every local table), warning with the number of
   changes not yet accepted by the server.
5. **Bundle**: supabase-js loads on first use (`core/supabase/client.ts`), so the app shell stays at ~204 KB gzip.
6. **Status honesty**: a new local change turns "Synced" into "Syncing…" at once, not only when the delayed push
   runs.
7. **E2E servers**: `:4173` is built with the Supabase variables blanked (local-only; the suite needs no
   secrets), `:4174` with the project from `.env.local`; `e2e/cloud.spec.ts` runs only when that file exists.

## Evidence

`e2e/cloud.spec.ts` against the hosted project (2 × green): signed-out redirect; device A signs in, adds a PDF,
highlights a line, the row reaches the server under A's user id; device B signs in, pulls the document and the
highlight; sign-out with removal empties B's database while the account keeps the data.

## Owner setup (Supabase Dashboard, not code)

- Authentication → URL Configuration: Site URL = the deployed app; add `http://localhost:5173` and
  `http://localhost:4173` to Redirect URLs, or magic links land on the Site URL.
- Authentication → Providers → Google: enable with a Google OAuth client, else "Continue with Google" reports
  "provider is not enabled".
